# Codex 引き継ぎ資料 — Chord Atlas（公開版）

このファイルは、次に開発を引き継ぐ Codex（および人間）向けのガイドです。
**「現状の把握」＋「壊してはいけない原則」＋「今後 自走して良いUX/デザインを続けるためのコツ」** をまとめています。
細かい設計仕様は [DESIGN.md](./DESIGN.md) を、依存・制約は [SECURITY.md](./SECURITY.md) を参照。

---

## 0. プロダクトの目的（最初に必ず読む）

アマチュアギタリストが **ギターを抱えたまま、練習中に** 使う道具。狙いはただ一つ:

> **少ない操作で、欲しいコード情報にすぐ届く。練習の邪魔をしない。また使いたくなる軽さ。**

情報量を増やす方向には行かない。機能を足すより「迷わせない・タップを減らす・デバイスを触る回数を減らす」が常に優先。

---

## 1. 現状サマリ（実装済み）

- 構成: 静的サイト。`index.html` + `src/styles.css` + `src/app.js` の3点だけ。ビルド不要。
- 画面（ハッシュルーティング `#lookup` `#key` `#identify` `#stock`）:
  - **押さえ方**: ルート×種類の2タップ、または名前入力でコードのダイアグラム＋構成音。
  - **キー**: 選んだキーのダイアトニックを「押さえ方つきで全コード一覧」。トグルで名前のみにも。
  - **判定**: 構成音（`ドミソ` / `C E G`）からコード名候補。
  - **ストック**: 複数コードをためて一画面で押さえ方を見比べる（進行の練習用）。
- デザイン: 淡い寒色背景 `#f4f6f9` ＋ 白い作業面 ＋ 青アクセント1色。PCは上部タブ＋2カラム（左入力／右結果sticky）、スマホは単一カラム＋下部固定ナビ。
- 表記: muuu.jp 準拠（`CM7` `Cm7` `CmM7` `Cm7♭5` `CaugM7` …）。
- 種類: 全19種を「よく使う / セブンス・6th / テンション / sus・aug・dim」の小見出しで塊化。

### 主要な関数・データ（app.js）
| 役割 | 場所 |
|---|---|
| コード定義（音程・表記） | `TYPES` |
| 種類のグループ分け | `TYPE_GROUPS` |
| 名前入力のパース（大小区別＋別名） | `TYPE_ALIASES` / `parseChordName` |
| 指板図SVG生成 | `renderDiagram`（各弦左に音名、度数は色） |
| 構成音チップ（重複排除） | `chordTones` / `toneRow` |
| 押さえ方の形データ | `OPEN_SHAPES` / `movableTemplates` / `getChordShapes` |
| 画面切替 | `setScreen`（`[data-nav]` で全タブ連動） |
| ストック | `readStock`/`addStock`/`removeStock`/`clearStock`/`renderStock`（localStorage `chordAtlasPublicStock`） |

## 2. 動かし方・確認方法

- ローカル: 任意の静的サーバでルートを配信（例 `python -m http.server 8787`）→ `http://127.0.0.1:8787/#lookup`。
- **ブラウザが `app.js`/`styles.css` をキャッシュする。変更が反映されない時は Ctrl+F5、または `?v=<時刻>` を付ける。**
- 変更したら **必ず PC幅とスマホ幅（375px）の両方** で見て、実際に操作して確認する。見た目の確認だけで終わらせない。

## 3. 壊してはいけない原則

1. **コードフォーム／指板図の音楽データは「正解の管理者」が別にいる。**
   `TYPES` の音程、`OPEN_SHAPES`、`movableTemplates`、ダイアトニックの綴り等の **音楽的な正しさは勝手に変えない・AIで創作しない**。
   本人の本実装 `C:\CodexProject\guitar-renshu\chord-guide.html`（CAGEDエンジン `movableShapeFor`）がフォームの正。
   UI・配色・レイアウト・情報設計だけを触る。音楽データに触る必要が出たら、まず確認する。
2. **要検証フラグ**: `movableTemplates` の `mMaj7` / `augMaj7` は公開版にデータが無く、標準ボイシングを暫定で置いている。本人データで差し替える前提。勝手に「正しい」と扱わない。
3. **ナビ連動**: `setScreen` は `[data-nav]` を一括トグルしている。タブを足す時は `data-nav` と画面idの規約（`#xxxScreen`）を守る。

## 4. デザインシステム（具体ルール）

トークンは `:root`（styles.css）。**色・余白・角丸・影・太さは下記の幅から外れない。**

- **2層構造**: 背景 `--bg #f4f6f9`（淡い寒色）の上に作業面 `--surface #ffffff`（純白）。これが「机に紙」を作る土台。
- **アクセントは青1色** `--accent #4c8dff`（選択は `--accent-weak #eaf2ff`）。黄色 `--pop #ffce4a` は極小ポイント（ブランドマークの押弦ドット）だけ。
- **面の仕切りは影ではなく 1px の実線**（`--line`）。影 `--shadow` は極薄。`backdrop-filter: blur` の濫用はしない。
- **角丸**: カード 12〜14px / 入力・行 10px。チップ・タブだけ pill（999px）で可愛げ担当。
- **フォントウェイト**: 本文 400 / ラベル・チップ 600 / 見出し 700 / コード名のみ 800。**900は使わない。**
- **文字サイズ**: ヒーロー級の特大H1は作らない。画面見出しは18〜20px。

## 5. UX原則：ギタリストの立場で考える（最重要）

「自分がギターを抱えて、左手がふさがっている状態」を毎回想像する。そこから逆算する。

- **タップを減らす / デバイスを触らせない。** 一覧で見えるなら開かせない（キー画面は全ダイアトニックを押さえ方つきで一覧表示にした）。
- **頭を使わせない（認知負荷を下げる）。** 英数字の羅列で考えさせない。例: 構成音は指板図の各弦の左に音名を直接出し、重複は排除した。
- **馴染みのもので迎える。** 初期表示は誰でも知っているオープンC（Eaugのような珍しいコードにしない）。第一印象で「コードの押さえ方サイトだ」と一瞬で伝わる。
- **主役は1つに絞る。** 1画面につき「来訪者がやりたい事」は1つ。それを視覚的な主役にし、検索などの代替手段や履歴は控えめに降格する。
- **ラベルは挙動と一致させる（正直さ）。** 「音名」と書いてあるのに音名を受け付けない、のような嘘を作らない。
- **タイトルは価値で言い切る。** 「コードを調べる」より「コードの押さえ方」。抽象語より、得られる物を書く。

## 6. 情報設計の型（迷ったらこの順で判断）

新しい要素を足す/並べる時は、必ずこの順序で考える:

1. **この画面に来る人の“第一の用事”は何か？** → それを最上段・最大面積の主役にする。
2. **代替手段（別の入口）は？** → 主役の下に、小さく・薄く。
3. **履歴・お気に入り等のショートカットは？** → 一番下、軽い見た目、区切り線で分離。コントロールと混同させない。
4. **似た見た目で違う機能を並べない。** 機能が違うなら見た目（サイズ・色・位置）で差をつける。
5. **チャンク化する。** 項目が多い時は小見出しで塊に分ける（種類セレクタの19種を4グループにしたのと同じ発想）。隠すより、見せたまま塊化する方が速いことが多い。

## 7. コード表記とデータの扱い

- 表記は muuu.jp に合わせる: `M7`(メジャー7) / `m7`(マイナー7) / `mM7` / `m7♭5` / `augM7` 等。`TYPES[].suffix` を変えれば表示は全箇所連動する。
- **`M7` と `m7` は大文字小文字だけが違う。** 名前入力のパースは `toLowerCase()` してはいけない。`TYPE_ALIASES`（大小区別＋別名）で照合する。別名（`maj7` 等）も受理する。
- 新しいコード種類を足す時は `TYPES`・`TYPE_ORDER`・`TYPE_GROUPS`・`movableTemplates`（フォーム）の4つをセットで更新する。フォームが無いと `base.maj` にフォールバックして誤った押さえ方が出るので注意（＝原則3-2）。

## 8. 既知の課題 / 次の候補

- **要対応**: `mMaj7` / `augMaj7` のフォームを本人データで差し替える。
- 提案済みの機能（ギタリストに効く順）:
  1. **カポ／移調**（開放弦で弾けるキーへ、または任意キーへ）。最有力。
  2. キー画面に**定番進行**（I–V–vi–IV 等）ワンタップ。
  3. ダイアトニックに対する**スケール/ソロのヒント**。
  4. **左利き反転**トグル。
- 判定→「コードを見る」でモバイルだと結果位置が分かりにくい。飛んだ先で結果へスクロールすると親切。

## 9. 自走するためのチェックリスト & アンチパターン

### UIを変更したら、出す前にこの問いに答える
- [ ] この画面の「第一の用事」は何で、それが視覚的な主役になっているか？
- [ ] ギターを抱えたまま、タップ数・スクロール量は最小か？
- [ ] 初見の人が、説明文を読まずに「何をする画面か」を一目で分かるか？
- [ ] ラベルと実際の挙動が一致しているか（嘘がないか）？
- [ ] PC幅とスマホ幅(375px)の両方で崩れず、操作が成立するか？（実機で操作確認した）
- [ ] コンソールエラーは無いか？

### 「AI生成・怪しいサイト」に見える手癖（やめること）
- ベタ塗りの強い背景色／グラデーション・グロー。
- 半透明ガラス（`rgba(...,.8)` + `blur`）の多用、濃い大きなドロップシャドウ。
- 何でも `font-weight: 900`、何でも角丸18〜24px。
- 英大文字の eyebrow（`CHORD LOOKUP` 等）、ランディングページ風の特大H1ヒーロー。
- 装飾・キャラクター・絵文字で“可愛さ”を足す（可愛げは余白・淡色・小さなアクセント1点で出す）。

### 今風で清潔に見せるコツ（やること）
- **足すより削る。** 今回の改善の大半は「要素を減らす」ことで達成した。迷ったら線・影・色・文字を減らす。
- 余白で区切る（カードや線を増やさない）。
- 1アクセント色を狭い面積に。色で飾らず、色で誘導する。
- 参考（Nani / Zenn）は“真似”ではなく、共通する設計原理（2層・1アクセント・線で仕切る・控えめな角丸）だけ抽出する。

## 10. 変更時のワークフロー（推奨）

1. このファイルと `DESIGN.md` を読む。原則3（音楽データに触らない）を確認。
2. 変更は `index.html` / `styles.css` / `app.js` の該当箇所に最小限で。既存のトークン・クラス・関数を再利用する。
3. PC幅・スマホ幅の両方で、実際に操作して確認（見た目だけで終わらせない）。
4. 表記・データ規約（§7）に触れる変更なら、4点セット更新と大小区別パースを忘れない。
5. 仕様が増えたら `DESIGN.md` を、引き継ぎに関わる方針なら本ファイルを更新する。
